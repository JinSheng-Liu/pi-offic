# 排版能力第一轮修改与验收

## 已实现

- 格式工具新增 `scope: text`：单个段落索引、准确原文、可选 occurrence（0 起），调用 docx4j 原生 search 和 Range.font；只改变选中文字。所有字体槽位同步写入并清理主题引用。
- 范围校验保护未选中文字和直接格式、段落属性、其他段落、包中其他部分；原生拆分文本运行不再被误判为正文损坏。暂只支持普通顶层文本段落；表格、字段、修订及其他复杂内联结构拒绝处理，不绕过保护。
- 四种分页属性：keepNext、keepLines、widowControl、pageBreakBefore，可读取直接设置、写入并保存重读。读取 null 表示未直接设置，不代表继承后的值。
- 范围操作和段落操作按顺序执行，DocumentStore 只在全部成功后提交一个版本；失败时不保留前面已执行的中间修改。
- Pi 工具 schema 与系统规则同步更新。按用户指定字体字号处理，禁止把混排整段误设为标题；不得将工具校验冒充全部需求/视觉验收。
- 右侧“版本历史”新增“检查当前页面”：读取编辑器当前 layout，检查孤立标题、短尾行、非末页明显底部留白，支持跳转。只读提示，不自动修改。文字修改后清除过时检查结果。
- 页面检查显示 fontMeasurement 和 fontSubstitutions，明确估算字宽、字体加载或替代状态。
- health 增加能力标识，前端遇到旧后端会提示重启并停止发送新的 AI 编辑请求，手动保存仍可用。
- 文件上传类型错误且正文非空时返回 415，不再静默创建空白文档；正常空请求仍可新建空白文档。
- 版本摘要显示操作项数，避免将重复段落/分节的累计计数误称为段落数。

## 尚未完成（不得宣称全部产品完成）

- 编辑器当前 fontMeasurement 为 fixed，未接入完整真实字体字节测量。小标宋、方正小标宋简体不可用，使用替代字体；因此当前编辑器分页和断行不是 Word 保真验收。
- 附件长标题短尾行已检测，但尚未自动进行语义断行优化。未偷偷添加换行或缩小字号。
- 页面检查目前为手动只读，尚未形成自动渲染—修正闭环，也没有完整的可持久化逐项需求验收模型。
- 页面检测当前仅覆盖顶层段落；不宣称覆盖表格内部、文本框、复杂分栏和所有专业排版规范。较大留白可能是有意排版，只作为提示。
- 页面记录通过固定版本编辑器的 surface.layout 访问。它是底层能力接口，需在依赖升级时回归，不另外维护分页引擎。
- 未进行 Word 实际打开验收、长期模型稳定性及压力测试。
- 后端仍需重启才能加载本轮修改；新增能力提示解决误用旧服务，没有声称实现了安全后端热更新。

所有测试副本位于 data/testing/documents 与 data/validation/layout，原文档未覆盖。用户服务未停止。
