# 长文档读取及 Tab 定位修复

## 原因与修改

真实论文测试中，分页扫描仍为每段返回完整格式并累积到对话历史；行距回读丢失规则；前导 Tab 缺少制表位信息与安全定位能力。

- 默认结构扫描只保留定位、160字文本摘要、层级、角色、图表和空白线索；截断有明确标记。
- indices 默认完整格式回读，也可显式 detail=formatting；摘要不能用于段内文本匹配或格式验收。
- 复用 docx4j effectivePPr 返回继承后 lineSpacing 和 tabStops，同时保留直接设置和默认制表间距。
- 复用 Pi transformContext，仅去重内容完全相同的成功 inspect_document 结果；不同版本、写入和错误不裁剪，原始会话不变。
- leadingTabPosition 仅支持明确索引、普通段落、单个前导Tab、无已有自定义制表位和缩进；保留文字，新增左制表位，保存后回读。
- 制表位未加入全局可变字段：仅在临时保护比较副本去掉本次受限新增目标，再运行原有保护；真实输出保留新增值并独立回读。

## 验证

先运行失败测试，分别复现完整属性扫描与缺失行距规则；修复后通过。单Tab定位同样先复现未支持再实现。

npm run check 通过：46项服务/技能测试、API集成、4项前端逻辑、DOCX引擎、Pi及构建。另追加断言确认全局保护仍拒绝任意制表位变化，定点测试通过。

同一份1173段原结构记录，按80段扫描：完整输出756283字符，精简输出190380字符，减少75%。这是JSON字符比较，不是全流程token或耗时下降比例。

真实论文的8个Tab段落默认间距为420twips（21pt），无自定义制表位；直接加24pt首行缩进不能等同文字最终起点。

## 边界

未做全文模型重跑与页面视觉验收。完全重复读取去重不是完整上下文预算系统；不同读取与长会话仍可能累积。制表位结构正确不等于所有编辑器渲染一致。复杂多Tab、既有制表位、列表、表格和混排图形拒绝自动覆盖。Skills保持72行。
