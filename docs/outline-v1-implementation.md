# V1 文档大纲实现与验证

左栏是单一文档大纲，显示文件名、来源、层级和折叠控制。移除调用 AI 修改文件才能显示导航的入口。

## 数据与定位

- 首选当前编辑器的 getOutline()，采用返回的 text、level 和 blockId。安装版 2.33 的层级从 0 起。
- 原生大纲为空时，使用公开 query({type: 'paragraphs'}) 读取当前编辑器段落，以保守规则识别独立短标题。只读当前编辑器数据，避免再次维护 docx4j 文档副本和持久导航索引。
- 规则结果标为“智能识别 · 规则识别，未修改文档”。识别不写文件、不新增版本、不请求模型。模糊标题留空，不自动猜测；用户仍可通过助手明确要求规范标题样式。
- 使用 findMatches 批量匹配当前正文段落，结合段落序号和起始位置消除同名标题歧义。blockId 必须来自编辑器结果，不生成假 ID。
- 点击使用 scrollToBlock。change 事件后清空旧位置，合并连续编辑后重读；重新加载或重新挂载也重新获取大纲。
- 折叠由 Vue 管理。活动章节读取编辑器渲染段落位置，在滚动、选择与窗口尺寸变化时更新；这部分依赖安装版本的 data-paragraph-id 和滚动容器标记，升级编辑器需要回归验证。

## 实际验收

2026-11-01 在本地 5173 页面执行：

1. 打开用户公文 v3，自动出现 6 个规则标题。点击最后标题，滚动位置变为 2392；回到顶部，活动项同步为第一个标题。服务端版本仍为 3，更新时间仍为 2026-11-01T07:56:24.258Z。
2. 原生 3 层标题测试文档显示 5 项。折叠第一章显示 3 项，展开恢复。两处同名标题分别跳到滚动位置 371 和 1389。
3. 在独立测试文档通过编辑器公开 replaceMatch 命令改名，列表更新；清空标题后列表减为 4 项。测试用 Vue 暴露句柄获取编辑器，生产组件不读取 Vue 私有实例。
4. 全部 Normal 样式的对应文档显示规则大纲；同名标题分别跳到 344 和 1251，折叠及刷新后重新定位通过。
5. 规则与折叠回归测试：node --test test/outline.test.mjs。

## 范围限制

不增加自动 AI 分类；模糊章节和标题正文混排不自动猜测。当前规则是保守提示，不等同于 Word 原生标题。原生大纲能力受编辑器 2.33 限制（其 getOutline 读取样式中的层级，非所有 OOXML 直接层级形式）；后续升级须验证。尚未覆盖超大型文档、所有虚拟滚动场景、复杂表格或文本框中的章节。未声称完成这些场景。
