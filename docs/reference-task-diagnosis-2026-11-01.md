# 参考文档恢复任务诊断

## 已确认根因

任务文档 d034fa48-213c-4461-8515-995895a0fe41，版本1。用户要求读取两份指定文件、比较内容、一致时从原稿生成独立副本，否则匹配后恢复格式。实际会话只有 inspect_document 一次成功调用，没有写入工具调用和处理异常。5173健康接口包含 document-commit-events，已加载新版后端。

产品当前只有 inspect_document、analyze_formatting、add_captions、apply_formatting、validate_document 五个Agent工具。inspect绑定当前id；没有参考文档附件/选择、两文件比较、参照恢复、另存指定文件工具。模型拒绝执行的主要原因真实，不是docx4j运行报错或旧后端。

## 实际文件核对

两文件存在于用户给出的E盘路径。上传文件与去除格式文件SHA256相同。2869个XML段落文本一致，23个表格、179行、650个单元格、205个drawing节点、7个sectPr数量一致；90个媒体文件哈希多重集合一致。正文和页眉页脚等故事的文字、域指令、正文Tab与换行序列一致。比较排除段落pPr/tabs中属于格式定义的tab，避免把制表位删除误判为正文改动。

以上尚未证明所有关系、对象内容和结构相同，也未渲染页面；不能直接声称全面保真。没有覆盖输入文件或生成恢复结果。

## 额外风险和覆盖缺口

1. inspect_document此次返回703227字符、1173个正文段落及650个表内段落，没有分页/按需取回。这是大文档上下文负担，未证明本次发生模型截断。
2. structure.mjs中段落文本上限1000字符、表格摘要500字符，不能作为全文一致性比较依据；此次正文段落没有达到1000字符。
3. 当前Workflow仅支持format/captions两类批次；拆分模块没有增加参考文档恢复能力。
4. 界面“对话结束”仅表示流结束，缺少结构化“未执行/部分完成/成功”任务结果；不能用SSE done当作格式成功。
5. 本次31项服务端和API测试通过，但没有覆盖双文档恢复。API集成使用本地确定性模拟模型，不能当作真实模型任务验收。
6. 题注候选正则会把以图X-Y开头的正文引用列为候选，候选识别不能当成确定关联。

## 修复顺序

先建立参考文档上传/选择和明确的文档ID，不让模型任意访问磁盘。增加确定性全文/结构/关系/媒体比较；内容等价时直接创建原稿字节副本，保留原件。内容不一致时先输出差异及可靠匹配，拒绝不确定覆盖。生成独立文档并返回产品下载入口；指定本地路径属于另外的受控导出能力。inspect改成摘要和分页读取，并明确截断标记。返回结构化执行结果。用此次两份实际文档建立端到端验收，而非只添加工具注册测试。
