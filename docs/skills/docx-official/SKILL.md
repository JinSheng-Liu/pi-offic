# 党政机关公文

## 适用范围

- 适用于明确的党政机关公文格式整理。
- 企业通知或普通告知书不因“通知”二字自动归入本类型。
- 依据用户文种、机关模板和公文要素组合确认适用性。
- 用户明确提供的规范版本和模板优先。
- 不凭记忆宣称符合 GB/T 9704 全部要求。
- 本技能不生成文号、印章、署名或公文正文。
- 用户仅要求字体调整时不擅自重做版头和版记。
- 段落与字体执行细节沿用公共技能。

## 输入与前置检查

- 读取用户要求的具体文种、模板和适用区域。
- 分页识别机关标志、文号、标题和主送机关。
- 继续识别正文层级、附件说明、署名与成文日期。
- 定位版记、抄送信息及现有分节，不按最后几段猜测。
- 检查独立标题与“一、”等段内标题是否混排。
- 记录中文与西文字体、缩进、前导 Tab 和行距。
- 核对用户是否要求页面边距及给出了明确数值。
- 无法取得规范正文时，只执行明确参数，不编造标准条款。

## 识别与决策

- 主送机关、正文、落款和日期有不同对齐职责。
- 不把所有非标题段落设为正文首行缩进。
- 独立层级标题与正文混排标题采用不同目标范围。
- 署名与日期需要成组检查，右对齐不等于位置合规。
- 附件说明和附件正文不是同一个区域。
- 现有机关标志不随正文字体统一而被覆盖。
- 空段可能承担版头间距，不以空文本为由删除。
- 不根据公文类型自动添加红线、印章或保密标识。

## 执行流程

- 建立公文要素到实际段落索引的对应表。
- 对确认正文应用用户指定字体、字号和行距。
- 对段内小标题使用准确 text，保持后续正文字体。
- 发文机关标志、文号、标题、正文分别用namedStyle定义公文·对应角色；不把红头当章节。
- 非章节outlineLevel设10，独立章节明确层级；不凭字号或颜色猜测。
- 主送、附件说明、署名、日期分别按要求处理。
- 分节页边距用 sections 操作，与段落格式分开。
- 页眉页脚或版记内容写入未开放时，单列未支持项。
- 执行后回读当前版本，保留尚不能确定的区域。

- 段内标题使用scope=characterStyle、styleName、单段indices、准确text和font；保留正文段落样式，不改变大纲层级。

## 验收要求

- 逐项核对文号、标题、主送、正文和落款的处理结果。
- 检查混排段内标题之后的正文未被一起改字体。
- 核对缩进与前导 Tab，避免数字正确但实际起点重复偏移。
- 检查附件说明与正文保持各自格式。
- 验证页面参数的单位与目标值，不能把 pt 当成 twips。
- 确认文字、日期、署名、分节引用未被改写。
- 版心、行数、印章空间和页面留白无渲染证据时待确认。
- 最终区分用户参数已落实与完整国标合规尚未验证。

## 案例与失败边界

- 案例：“一、提高认识。”与正文同段，只强调该标题文字。
- 案例：用户明确要求正文三号，不据此把机关标志改为三号。
- 案例：附件包含表格，转入对象技能处理而非全文统一缩进。
- 反例：普通公司通知自动套用党政机关文号与红头样式。
- 反例：将主送机关和成文日期一律首行缩进两字符。
- 反例：只检查字号就宣称公文符合完整国家标准。
- 若规范与用户参数冲突，指出具体差异并确定优先依据。
- 工具无法表达的特殊定位应说明，不能用近似结果冒充达标。
