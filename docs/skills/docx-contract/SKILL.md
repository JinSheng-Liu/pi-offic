# 合同协议

## 适用范围

- 适用于合同、协议及其条款和签署区的格式整理。
- 根据标题、当事人、条款、签署信息的组合识别。
- 报告中提到“甲方”不代表整份文档就是合同。
- 仅处理格式，不提供条款补写或法律有效性判断。
- 用户要求只改字体时，不扩大为重新编号或调整条款顺序。
- 附件可以是表格、技术说明或报价，按各自区域处理。
- 通用字体、版本和失败规则沿用公共技能。
- 签署表格或附件图表需要时加载 docx-objects。

## 输入与前置检查

- 读取明确的目标条款范围和合同模板要求。
- 分页定位标题、当事人信息、条款、附件与签署区。
- 区分条款标题和同一段中的条款正文。
- 检查自动编号、手动编号及悬挂缩进是否混用。
- 记录填写横线、制表符、空格和签字留白所在段落。
- 读取 cells 视图，识别无边框签署表格中的实际段落。
- 查看引用条款、域和书签是否涉及待处理范围。
- 无法确认某个空段是否用于盖章时保留，不猜测删除。

## 识别与决策

- 法律文字、金额、日期、当事人名称均保持不变。
- 签署区不适用普通正文的统一首行缩进。
- 编号与条款文字之间的 Tab 可能控制对齐，应保留并检查。
- 独立条款标题可以单独强调，段内标题仅修改准确文本范围。
- 不为视觉统一把多级条款编号转成新编号系统。
- 双方信息布局需保持对应关系，不因无边框就改成正文。
- 报价表数字列与备注列不能一律居中。
- 合同空白可能承担填写、签字或盖章功能，不能批量清理。

## 执行流程

- 先列出可修改区域和需要保留的签署、填写区域。
- 对确认的条款正文使用明确 indices 设置用户要求属性。
- 独立标题与条款正文分别设置，不覆盖全部 Normal 段落。
- 段内强调使用 scope=text，并对重复文字指定 occurrence。
- 处理签署区时先读取 cells，使用其 paragraphIndices。
- 修改表内水平对齐不得声称已改变单元格垂直对齐。
- 附件规则与主合同不同则拆成独立操作组。
- 结构保护失败时停止该处理链，不改写内容来绕过失败。

## 验收要求

- 逐项回读条款目标字体、字号、缩进及间距。
- 对比目标条款文本，检查金额、日期、名称未被改写。
- 检查条款编号显示依赖的编号和缩进仍然存在。
- 核对填写空白与签署文字未被删除或新增。
- 验证表格指定单元格对齐，抽查邻近未指定单元格未受影响。
- 检查附件要求与主合同要求分别落实。
- 留出签字盖章的实际页面空间需页面检查，不能只凭空段数确认。
- 最终说明格式验收范围，不宣称法律合规或签署有效。

## 案例与失败边界

- 案例：只将第八条标题加粗，应准确选标题文字而非整条正文。
- 案例：甲乙方签字在两个单元格中，分别使用真实段落索引。
- 案例：用户要求全合同字体统一，可统一字体但仍保留区域缩进。
- 反例：删除空行后声称签署页更美观。
- 反例：把合同中手动条款编号替换为自动编号而未获要求。
- 反例：自动补充缺失签名、日期或法律条文。
- 发现用户要求涉及未支持的签章位置时，说明限制并完成其他明确项。
- 没有行业模板证据时，不用“标准合同版式”作为验收结论。
