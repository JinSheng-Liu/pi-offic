# 动态文档任务与结束判定

## 需求和范围

新任务不生成固定的页面、目录、图表等栏目。发送后先读取用户涉及的真实文档范围，再建立对应用户要求的计划。正文改字体不授权重排封面，原文没有的结构不自动添加。宽泛排版要求按相关 skill 明确采用的格式标准。

Pi AgentSession 继续管理会话、工具循环、持久化和上下文压缩；任务账本只管理文档特有的范围与结束条件。

## 状态

- pending：尚待执行；未检查、未覆盖不是受阻。
- awaitingVerification：已经执行，等待回读检查；宿主继续推进。
- addressed：模型报告已按依据处理，不等于独立需求覆盖或视觉验收通过。
- blocked：必须关联本任务当前版本真实失败的工具调用和具体目标，保存失败记录；清单工具自己的报错不能作为依据。
- needsDecision：需要用户决定，必须给出具体问题；其他独立待办仍继续。
- notApplicable：提供当前版本和原文检查依据。

空清单不代表修改请求已完成。咨询不自动生成修改计划。仍有待执行或待核验项目，宿主继续同一任务；无进展、次数上限、取消与异常明确报告。

## 恢复与展示

新清单使用 schemaVersion 2。继续旧版任务时不继承固定分类，以已提交回执和当前文档重建范围。新版受阻项在继续时重新检查；旧错误不能直接作为当前失败证据。

实时事件及刷新恢复都显示动态清单。清单显示自身状态，去掉通用工具步骤的重复“待执行/已提交”标签。需要用户决定的问题必须可见。

## 验证与边界

任务控制测试覆盖动态初始化、缺计划继续、假受阻拒绝、待核验继续、旧任务迁移、取消与无进展退出。API 集成实际模拟工具失败和清单调用，不只验证函数。

本轮没有实现自动目录排版、浮动对象布局或页面视觉验收。真实工具错误存在不意味着程序已证明它与该需求的语义对应；addressed 仍由模型提供依据。后续需要基于具体文档对象和验收器进一步约束，不能宣传为全文自动质量保证。
